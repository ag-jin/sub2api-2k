## 内容

### 新增：设置页「立即执行」

后端（平台无关注册表）：
- `RegisterPlatformFeatureImmediateRunner(platform, key, fn)` 执行者注册表；
- `RunPlatformFeatureNow` 派发：未注册→**404**、已注册无执行者→**400**
  （两者区分，免得拼错 key 被含糊成 500）；
- `POST /admin/settings/platform-features/run`（审计 action
  `admin.settings.platform_feature.run`）；
- GET 的 DTO 新增 `supports_immediate_run`（由注册表回答，前端不猜 key）；
- 三个 codebuddy 功能在各自 wire provider 里注册执行者。

**不读开关、不读窗口**：开关管自动排程；窗口更不该管——"错过窗口想补一次"
正是本能力要解决的场景。与各平台既有手动端点口径一致。

前端：按钮 + 结果文案；逻辑放在 `usePlatformFeatures` composable
（SettingsView 是上万行 SFC，代码库既有约定要求抽出来才可测）；
i18n 双侧。

### 修 bug：夜猫窗口跨午夜去重失效（**v0.1.203 引入**）

夜猫窗口 23:00–08:00 跨零点，去重键用了**当前日历日期**：
23:30 → 09-29、次日 07:30 → 09-30，两次都认为"今天还没跑"→ **同一夜跑两轮**。
探针实测确认（`23:30 → localDay=2026-09-29 / 07:30 → localDay=2026-09-30`，
两者 `inWindow=true`）。

后果有限（夜猫通道内部还有账号级台账兜底），但调度层去重确实失效。
修法：`codeBuddyGrowthNightAnchorDate`——日出前那段（<08:00）归到前一日，
使同一个夜锚定到同一日期。

## 事故 / 教训

### 本次：CI lint 再次拦截（连续第二个版本）
`b65b335f7` 之前，CI 的 golangci-lint 报
`platformFeatureImmediateRegisteredKeys is unused`。本地
`gofmt`/`go vet`/`go test` **全绿**，只有 CI 的 `unused` 能发现。

这与 v0.1.203 是**同一类问题**（那次是 unused + QF1002 三处），
连续两版因同一原因重打 tag。**已从流程上修**：

1. 工作流文档 §第 2 步补上"lint 也要本地跑"，含命令与坑
   （`.scratch/bin/golangci-lint`，**必须用本机 go1.27 构建**，
   预编译版是 go1.26 的会因 "Go version lower than targeted" 拒绝启动）；
2. 已在本机装好 v2.13.0（与 CI 同版本），本版发 tag 前实测 `0 issues`。

### 过程教训（值得记）
**"本地全绿"不等于"CI 全绿"**：本机缺 golangci-lint 时，
`unused`（死代码）与 `QF1002`（staticcheck 写法）两类**完全不报**。
发 tag 前必须把 lint 纳入本地门禁，否则每次都要
"修 → 重打 tag → 重跑三条流水线"（约 15 分钟 + 一份作废制品）。

### 另一条（v0.1.203 教训的重申）
**断言 JSON 而不是结构体**：本版新增的 `supports_immediate_run` 契约测试
刻意解成 `map` 断言实际字段，并做了变异验证（移除赋值 → 立刻红）。
这正是 v0.1.203 门禁 C 抓到缺陷后确立的做法。
